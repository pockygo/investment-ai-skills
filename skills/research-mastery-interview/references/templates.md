# 模板

## A. 命题台账（访谈前在内部建，不必给用户看）

```markdown
| # | 命题 | 用户原结论 | 支撑数字 | 口径 | 可证伪条件 | 备注 |
|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |
```

用法：每条命题至少有一个数字或一个出处；没有的标“待验证”，优先拿来出题。

## B. 访谈原稿

```markdown
# <主题>「学懂了吗」访谈原稿

> 目的：检验对《<材料名>》的掌握程度，不写文章，只做诊断。
> 规则：每轮只问 1 题；根据上一轮回答动态追问；原话一字不改记录；最后出诊断，不替用户脑补。
> 判定依据：<报告> + <财务表> + <其他材料>。

## 访谈路线

1. 技术/商业底座
2. 上游
3. 中游
4. 下游
5. 财务与周期
6. 一级市场
7. 反证

---

## 第 1 轮

**问 1（<考点>）：**
<问题>

<一字不改>

**点评：** <判定 + 对在哪 + 缺口>

**追问 1：** <下一题>

**答 2：**
```

> 依据：<N> 轮问答（原话见 `学习检验_访谈原稿.md`）＋ <材料>
> 结论口径：只评“能否经得起尽调追问”，不评报告写得好不好

## 一、总评

## D. 开场话术（可直接改）

> 我按“一次一题、顺着你的回答追问”的方式来做，不预先给题单。你用语音随便说，错别字和口语都没关系，我按原意理解；答不上来直接说“不会”，这比硬编更有诊断价值。你的原话我会记在 `学习检验_访谈原稿.md`，最后给你一张掌握度诊断。

## E. 结束话术

> 诊断已写入 `学习检验_诊断报告.md`。下一步建议只做一件事：<动作>。如果继续，我建议从 <最薄弱的模块> 开始补，因为它是其他判断的地基。

## F. 评分参照

| 分数 | 含义 | 能做什么 |
|---|---|---|
| 90–100 | 能扛投决追问，能自己设证伪条件 | 投决、对外路演 |
| 80–89 | 逻辑清楚，偶有口径错误 | 内部讨论、初筛 |
| 70–79 | 骨架清楚，机理/证据有缺口 | 初筛，需人把关 |
| 60–69 | 能复述结论，一追就露馅 | 只能做资料整理 |
| <60 | 还没入门 | 建议重读材料 |
