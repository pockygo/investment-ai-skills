# IPO 招股书研究流水线

## 档位选择

| 档位 | 适用场景 | 流程 | 相对成本 |
|---|---|---|---|
| **quick** | 项目初筛、快速判断值不值得深研 | 合并模块（6 个子代理）+ 跳过反哺修订 | 约为 deep 的 1/3 |
| **deep** | 确定要深研的项目 | 11 个独立模块 + 问询反哺 + 修订留痕 | 完整成本 |

用户未明确档位时**默认 quick**，并在交付时告知可升级 deep 补跑反哺修订。两档的转换、索引、疑点清单、问询解析、终稿抽查完全相同。

## quick 档工作流

1. **转换与索引**：同 deep 档（见下，MinerU 主路不变）
2. **招股书提取**：按 `prompts/quick/Q1`–`Q5` 五个合并模块并行执行（Q2=行业与竞争、Q3=财务与利润质量、Q4=经营链条、Q5=股权与募投），输出 `extracts/QN_*.md`
3. **疑点清单**：执行 `prompts/12_疑点清单.md`（输入改为 Q1-Q5 的提取结果）
4. **问询函**（如有）：执行 `prompts/20_问询函解析.md`，与疑点清单对照；新规则沉淀到 `rules/疑点规则库.md`
5. **直接成稿**：按 `prompts/30_研究报告模板.md` 组装，素材 = Q1-Q5 + 12 + 20（无 v2，问询新增数据由组装代理直接合并引用，出处标"一轮/二轮问询 pXX"）
6. **验收**：同 deep 档（抽查 8-10 个关键数字）
7. **导出 HTML**：同 deep 档第 6 步（必备收尾步骤）

## deep 档三遍工作流

1. **转换与索引**（每个项目一次）
   - `python pipeline/convert.py <pdf> <项目目录>/md --name prospectus --backend auto`
     （主路 MinerU，自动降级 docling → pdftotext；产物带 `<!-- pN -->` 页码锚点）
   - `python pipeline/build_index.py <md> <项目目录>/index` 生成 `_sections.json` 和 `_tables.json`
   - 问询函同样转换，命名 `inquiry1` / `inquiry2`……
   - **保真验证**：抽 3-5 张关键表（前五大客户、分产品毛利、历次增资）与 PDF 原页面对照。

2. **第一遍：招股书提取**
   - 按 `prompts/01`–`11` 逐模块执行（可并行子代理，每个子代理只读自己章节）。
     每个模块输出到 `extracts/NN_模块名.md`，格式见各 prompt 内的输出契约。
   - 最后执行 `prompts/12_疑点清单.md`，结合 `rules/疑点规则库.md` 生成疑点清单。

3. **第二遍：问询函**（无问询函则跳过）
   - 执行 `prompts/20_问询函解析.md`，与疑点清单对照（命中/新增/未命中）。
   - 新发现的通用检查规则追加到 `rules/疑点规则库.md`。

4. **第三遍：反哺与成稿**
   - 执行 `prompts/21_反哺修订.md` 修订各 extract。
   - 按 `prompts/30_研究报告模板.md` 组装 `report/<公司简称>.md`（公司简称取通用短名，如"猎奇智能"，不带"股份/有限公司"等后缀）。

5. **验收**：从终稿抽 8-10 个关键数字回溯 MD 原文核对，附抽查表。

6. **导出 HTML**（必备收尾步骤，不可省略）
   - `python pipeline/md2html.py <项目目录>/report/<公司简称>.md <项目目录>/report/<公司简称>.html --title "<公司名> IPO 研究报告"`
   - 该脚本依赖 Python `markdown` 包；若当前环境未安装，在项目工作目录建虚拟环境（`python3 -m venv .venv && .venv/bin/pip install markdown`）后用 `.venv/bin/python` 运行，不要污染系统 Python。
   - 产物为带侧边目录的独立 HTML（无外部依赖，离线可读）。

## 项目目录约定

```
projects/<公司名>/
├── md/         # 转换产物（prospectus.md, inquiry1.md, ...）
├── index/      # *_sections.json, *_tables.json
├── extracts/   # 模块中间产物
└── report/     # 终稿（<公司简称>.md + <公司简称>.html + 验收抽查表.md）
```

## 全局原则（所有模块适用）

- **每个关键数据必须带出处**：`（招股书 pXXX）` 或 `（一轮问询 pXXX）`，页码以 MD 中的 `<!-- pN -->` 锚点为准。
- **区分事实与推断**：招股书原文是"事实"，模块作者的判断标注【分析】。
- **市场规模等第三方数据必须标注来源机构与口径**（如"弗若斯特沙利文，2023 年，中国口径"），并提示其为发行人付费委托、倾向乐观。
- **金额单位统一为万元**，原文为元/亿元的换算后注明。
- 找不到的数据写"未披露"，**禁止编造**。
