# 上市公司定期报告查找与归档

交付可打开、可追溯的报告原件，说明每个公司、每个目标期间的取得情况。把“下载了文件”和“取得了指定报告”分开判断。

## 确定边界

- 从当前对话、已有名单和目录恢复范围。“类似的”“再补几年”延续原有公司、排序、目录和年度口径，不自动扩大清单。
- 明确公司、报告类型、期间、核验日期、保存位置。已有授权直接沿用；仅询问无法推断且影响交付的信息。用户未指定目录时使用任务工作目录，不擅自写桌面。
- 仅下载要求的期间及必要的订正／补充资料。已有任务增量更新，保留原文件和记录。只要求下载时可附轻量清单；要求“类似上次”且上次含Excel时更新原台账，不自动扩展为财务分析或投资报告。

## 1. 先锁定主体和期间

建立“公司—目标报告期间”矩阵，再批量下载。

- **主体**：上市主体全名、历史名称、市场、代码。代码保存为文本，保留前导零；跨市场代码附市场以免重名。
- **关系**：母子公司、双重上市分别处理。同一主体A/H上市不重复计数；母公司报告注明集团口径。历史并购、重组前后的范围可能不同。
- **期间**：区分出版年份、标题年份、会计年度、实际起止日期。沿用已有台账约定；首次跨市场任务需要统一标签时可按财年起始年归档，并先说明。始终保存原始标题和实际日期。
- **截至日**：按核验日或用户指定日期判断“最新”“已披露”。未结束的期间不能标为应已披露，预告发布日期不代表报告已发布。

市场路径和文件名称见 [references/markets.md](references/markets.md)，只读涉及的市场。

## 2. 从目录找到原件

优先发行人IR资料库、监管／交易所公告库；搜索引擎和可信镜像用于定位、回退和交叉核对。文件身份靠原件内容确认。

1. 先找多年报告的目录页，一次提取目标年份的标题、日期、下载地址，减少逐份搜索。
2. 动态目录可读取页面实际使用的公开接口或浏览器显示的链接。保留公告／目录页和PDF地址，不把一家公司的接口参数硬套到其他公司。
3. 搜索组合公司名／代码、年度、当地正式文件名称；历史更名同时查旧名。区分全文、摘要、业绩公告、演示稿、综合／可持续发展报告。
4. URL里的年度、报告期数、公告编号只用于发现候选文件，不能据此确认年度。
5. 失败时依次试官网其他已公布链接、监管／交易所原件、可信镜像。先访问公告页、使用普通匿名Cookie再下载属于正常流程；遇到登录、付费或限制则换合法公开来源或记录受限，不绕过访问控制。

适度并发，同一来源连续限流时降低并发并有限重试。避免多个进程覆盖同一清单。已有合格文件复用，下载临时文件验证后再原子移动到最终位置。

## 3. 校验文件和内容

- HTTP成功、PDF扩展名、文件较大都不能证明正确。检查PDF文件头、可解析性、页数，再核对封面或正文中的公司、标题、报告起止日。完整年报合理页数因市场而异，不设统一最低页数代替判断。
- 分清完整年报、审计财务报表、业绩公告、摘要、季报、IPO历史财务。仅取得审计报表时注明范围；用户要求完整年报而缺业务／治理部分时，不悄悄记作完成。
- 原件与订正报告成组保存。局部订正保留原件；发行人明确提供整份替换稿时以更正版为主，记录关联关系。
- 文本提取异常先用PDF渲染、其他解析器或必要的OCR。乱码、扫描件和搜索未命中不能证明身份／年度错误，也不能当作验证通过。
- 记录来源、核验日期、字节数、页数和SHA-256。相同哈希被标成不同年度时复核，防止多个链接返回同一文件。

附带的离线助手只检查PDF结构并提供文本线索，不能判断报告类别、合并范围和法律身份：

```bash
python scripts/verify_pdf.py /path/report.pdf --identity '公司中文名|English Name' --period '2022.*2023'
```

使用环境已有的 `pypdf`；不可用时用可用解析／视觉工具，不擅自安装依赖。`--identity`、`--period`可重复传入，各表达式均须命中；同一表达式内用 `|` 表示可选名称。未命中转人工／视觉核对，不直接作内容错误结论。

## 4. 缺失项和补充资料

- 区分：已取得且核验通过、已下载待核验、截至日未见披露、未检索到独立报告、下载受限／失败。
- “未见披露”依据截至日的官方目录检索结果；搜索引擎没搜到只能说未检索到，不宣称从未披露或不会发布。
- 未披露半年报不能用上年半年报或当年一季报替代完成；补充最近一期时注明实际日期及类型。
- 上市前年报缺失可查同主体法定财务公告、IPO审计历史财务等，核对期间、单体／合并和完整性。旧母公司集团财报不自动等于目标公司年报。
- 同一IPO可关联多个期间，但只计一份实际文件；部分财务公告、订正报告不能增加已完成目标报告数。

## 5. 归档与台账

遵循用户排序，产业链任务可从上游至下游，其余沿用名单。每家公司一目录，文件名含公司、归档年度／期间和必要类别，原始标题保留在台账。

```text
研究资料/
  01_公司简称_市场代码/
    公司简称_2022年报.pdf
    公司简称_2022年度订正报告.pdf
  财报下载台账.xlsx
  下载记录.json
```

字段与计数规则见 [references/records.md](references/records.md)。Excel沿用已有布局；新建可用“公司与下载总览”和“财报下载明细”两表。制作Excel时使用环境可用的 spreadsheets 技能，无需Excel时不依赖它。

增量更新以公司、实际期间、类型建立稳定键，不按行号关联。更新后核对旧文件哈希、目标矩阵、新增文件数及缺失项。链接指向最终位置，移动资料后复核。

## 交付检查

- 每个目标期间均有状态，缺失原因具体，资料类别和期间已核对，不确定项保留待核验。
- 完成数按唯一目标期间统计，补充资料和实际PDF另算，三者可互相解释。
- 保留真实来源；Excel可筛选、代码保留零、日期可排序、本地及来源链接有效；检查受影响的公式和版式。
- 最终简述保存位置、新增完整报告与补充数量、未取得项、台账入口，不将资料收集写成投资结论。
