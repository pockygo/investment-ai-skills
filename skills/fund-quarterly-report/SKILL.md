# 基金季度运营报告

## 核心原则

- 始终以用户指定的最新主报告为底稿；只操作副本。
- 用户已手工修改过的版本优先级最高。保留其修改，不回退、不重复改动用户明确说“不用再改”的内容。
- 使用 Documents 技能处理 DOCX，并执行“编辑 → 结构校验 → 渲染逐页检查”的闭环。
- 复制已有段落、表格列、表格行和编号定义；不要重建可复用的格式。
- 项目顺序必须同时体现在投资概况表、正文项目章节和目录中。
- 正文只陈述已核实事实，不出现“根据项目表”“现有材料显示”“本报告未作推算”等生成过程措辞。
- **季度更新时冻结基础项、只刷新变化项**（见下方“季度更新铁律”），这是最容易出错、也是最常被用户纠正的一条。

## 季度更新铁律：冻结基础项，只刷新变化项（模式 A / B 通用，优先级最高）

拿到上一期（如二季度）基金报告做本期（如三季度）更新时，**必须逐项目区分“静态基础项”与“动态变化项”**。

### 冻结（原样沿用，一字不改）

- `(1)主营业务` 正文：深拷贝上一期报告对应段落 XML，文字不改。
- `(2)投资时投资亮点`：三角小标题的条数、文字及其正文全部原样沿用。“投资时投资亮点”是投资时点的固定快照，不随后续经营变化而改写。
- 冻结项**不得**因“项目表里有更完整的表述”“措辞可以更精炼”“顺序可以更合理”而重写、精简、换序或替换小标题文字。上一期报告是用户已定稿的版本，优先级最高；跨期重写会让同一项目在不同季度报告里措辞不一致，等同于回退用户的手工修改。
- 实践上应把上一期报告的项目块当作“半成品底稿”深拷贝，只替换动态段落，而不是按项目表重新撰写整块。

### 最小必要增补（唯一例外）

- 仅当公司确实发生**重大变化**（新增主业、公司更名、实际控制人变更、重大资产重组等）时，允许在原有段落基础上做**最小必要增补**：补一句说明该变化，其余文字不动。
- 增补前先向用户说明并确认，不自行判断改写。

### 刷新（本期必须重算/替换）

- **基金投资信息段**：本季度是否有新一轮融资（投前/投后估值、融资金额、新增注册资本、投资方及金额）、我方是否参与、**持股比例是否被稀释**、最新持股口径与在投估值。
- **`(3)经营情况`**：换成最新一期财务报表（期间列见“5. 项目表格”）＋重写经营说明（货币资金、毛利率、经营现金流、口径变化、异常科目）。
- **`(4)退出计划及退出收益`**：退出进展、协议/回购条款变化、按最新一轮单价重估的对应估值与收益。

### 项目范围

- 上一期报告中有、项目表中没有的项目：**不出报告**（用户明确要求时除外）。
- 项目表中有、上一期报告中没有的**新投项目**：`(1)`—`(4)` 四节全部新写（新项目无“上一期版本”可冻结）。

## 任务类型判定

先判定用户要的是哪一种输出，再选择工作流：

- **模式 A：更新基金报告**。触发词：生成/更新/重排“季度基金报告”“年度运营报告”，把“多个项目加入基金报告”，更新“投资概况/基金财务指标/目录”。→ 执行下方“工作流程”，输出完整基金报告 DOCX。
- **模式 B：单项目投后报告**。触发词：用户只说“写/生成/做 XX 项目（如 CVS）的投后报告”，没有要求更新基金报告时。→ 执行“单项目投后报告模式”，只输出该项目的独立 Word（对应基金报告中 4.2.x 项目章节的内容）。
- 不确定时（如既提到项目又提到基金报告）默认按模式 A，并在交付时说明；若用户明确“只要这个项目的 word”，按模式 B。

## 输入识别

- 主报告 DOCX：基金基本情况、投资概况、已有项目、基金财务指标、目录。模式 B 下主报告仅作格式模板，不更新。
- 项目 DOCX：单个项目的投资信息、主营业务、股权表、投资亮点、经营情况、退出安排。
- 项目表 XLSX：项目投资明细、股权、季度经营数据。
- 基金财务 XLSX：基金资产负债表、利润表、现金流量表。
- 用户指定的项目顺序、统计截止日、字体或格式要求。

## 工作流程

### 1. 复制并盘点

1. 将主报告复制到可写工作区和输出目录。
2. 用 `scripts/dump_docx.py` 或 python-docx 按正文顺序导出段落、样式、表格和 run。
3. 识别：
   - 投资概况说明段；
   - 投资概况表；
   - `4.2` 各项目块的开始和结束；
   - 第五部分基金主要财务指标表；
   - TOC 域、目录结果段落和目录级别；
   - 主报告中可作为格式权威的参考项目，通常为首芯、盛欣科。
4. 核对所有输入文件可读、项目数量与用户描述一致。

### 2. 确定项目顺序

按用户给定顺序建立唯一项目清单。以下三处必须逐项一致：

1. 投资概况表的序号；
2. `4.2.1`、`4.2.2`……正文项目章节；
3. 目录中的项目条目。

若已有项目位于错误位置，复制完整项目 XML 块后删除原块，再在目标位置插入；不得只改编号而不移动内容。

### 3. 更新基金投资概况

- 更新统计截止日、项目数量、投资金额合计、占基金认缴规模比例。
- 投资金额取基金实际出资口径；SPV 项目取基金对 SPV 的实际出资。
- 投资比例：

  `投资金额合计 ÷ 基金认缴规模`

- 扩展投资概况表时，深拷贝模板空白行或相邻项目行，再仅替换文字。
- 保留列宽、边框、底纹、字体、对齐和合计行格式。
- 删除空白占位行；合计金额必须等于逐项目金额之和。

### 4. 合并项目章节

项目结构统一仿照主报告参考项目：

1. `4.2.n、公司全称`
2. 基金投资信息段
3. `(1)主营业务`
4. 主营业务正文及股权结构
5. `(2)投资时投资亮点`
6. 带三角符号的亮点子标题与正文
7. `(3)经营情况`
8. 财务表和经营说明
9. `(4)退出计划及退出收益` 或模板既有同义标题
10. 退出说明

#### 项目标题

- 深拷贝主报告已有项目标题段落。
- 只替换编号和公司名称。
- 保留与参考项目相同的 outline level，使项目标题进入目录。

#### 项目间距

- 相邻项目之间固定保留一行空白。
- 最终检查每个项目标题前恰好有一个空白普通段落。

#### 主营业务

- `(1)主营业务` 是小标题。
- “主营业务”下面第一段必须是普通正文，不得使用 Heading 样式或 outline level，否则会错误进入目录。
- 第一段首行缩进必须与其他正文一致；直接复制参考正文段落的缩进设置，通常为首行缩进 2 个中文字符。
- 后续正文保持同样的字号、行距和缩进规则。

#### 投资亮点及三角小标题

- `(2)投资时投资亮点` 是小标题。
- 亮点下面每个子标题必须显示与参考项目一致的小三角。
- 不得沿用项目源文件的自动编号；源文件编号可能渲染为“第一条、第二条”。
- 从首芯或盛欣科的三角子标题深拷贝以下属性：
  - `w:numPr`，包括相同 `numId` 和 `ilvl`；
  - 悬挂缩进和左缩进；
  - 行距、段落字体和加粗属性。
- 仅替换子标题文字。正文段落不得带三角编号。
- 校验每个亮点子标题使用同一个参考编号定义；不得手工输入 Unicode 三角符号。

#### 字号规范

若用户未另行指定，采用本基金报告的最终口径：

- 小标题：四号，14 磅。包括各级项目小标题、`(1)`—`(4)` 和投资亮点三角子标题。
- 普通正文：小四，12 磅。
- 表格文字：小四，12 磅。
- 封面主标题、目录标题和基金一级章节标题优先保留主报告模板；除非用户明确要求“全文统一”。
- 同时设置 run 字号和必要的段落默认 run 属性，避免 Word/WPS 继承出不同字号。

### 5. 项目表格

- 直接深拷贝项目 Word 中的股权表和财务表，保留表格结构、底纹、边框和列宽。
- 若需调整字号，仅修改单元格 run，不重建表格。
- 股权表不得有空白尾行；合计行保持加粗。
- 不得张冠李戴：Q1 或 1—4 月数据不得标成 Q2 或其他期间。

#### 财务表期间列规则（滚动窗口）

期间列 = **前两个完整年度（如有）＋ 当年各期累计（截至报告期）**；报告期本身已构成完整年度时，当年直接以“年度”列示，不再拆季度累计。

| 报告期 | 期间列 |
| --- | --- |
| 2026年三季度 | 2024年度、2025年度、2026年1-3月、2026年1-6月、2026年1-9月 |
| 2026年四季度 | 2024年度、2025年度、2026年度 |
| 2025年三季度 | 2023年度、2024年度、2025年1-3月、2025年1-6月、2025年1-9月 |

- “如有”：公司成立较晚或未取得某年度报表时，该列直接省略；不留空列、不推算、不编造。
- 当年缺某期：有几期填几期；未到季末的按实际期间命名（如 2026年1-4月、2026M1-2），不折算成季度。
- 增加列时深拷贝模板列（见 `scripts/copy_table_column.py`），保持列宽、边框、底纹与表头灰底，不要重建表格。
- 表内只放资产负债表/利润表科目（营业收入、净利润、总资产、净资产）；货币资金、毛利率、经营现金流、口径变化写在表下经营说明。
- 资产负债表科目取期末时点数；利润表和现金流量表取当年累计数。

### 6. 更新基金主要财务指标

从基金财务 XLSX 读取报告期数据，金额从元换算为万元，通常保留两位小数：

- 营业收入
- 营业成本
- 管理费用
- 财务费用
- 利息收入
- 投资收益
- 公允价值变动收益
- 营业利润
- 净利润
- 货币资金
- 交易性金融资产
- 资产总计
- 经营、投资、筹资活动现金流量净额

季度报告中的利润表和现金流量表使用当年累计口径。新增期间列时深拷贝最近期间整列，再修改表头和数值，保留历史列及全部格式。

### 7. 更新目录

- 正文项目标题使用与参考项目相同的目录级别。
- 普通正文、主营业务首段、经营说明和亮点正文不得包含 Heading 样式或 outline level。
- 项目顺序和编号变化后必须更新目录。
- 若 Word/WPS 或 LibreOffice 可用，实际重算 TOC 和页码后保存。
- 无可用排版引擎时：
  - 在 `settings.xml` 设置 `w:updateFields w:val="true"`；
  - 将 TOC/页码字段的 `w:fldCharType="begin"` 标记为 `w:dirty="true"`；
  - 结构校验目录域仍存在；
  - 明确告知用户打开 Word/WPS 后会重算目录和页码，不能声称已完成静态页码渲染校验。

## 单项目投后报告模式（模式 B）

用户说“写/生成 XX 项目的投后报告”且只指单个具体项目时，采用本模式：**只产出该项目章节的独立 Word，即基金报告中 `4.2.x` 项目块的内容**，不更新投资概况表、基金财务指标、目录，也不新增/重排其他项目。

### B0. 该项目的上一期报告已存在时（季度更新）

当上一期基金报告中已经有该项目章节，本节按“**季度更新铁律**”执行：

- `(1)主营业务`、`(2)投资时投资亮点`：从上一期报告**深拷贝原样沿用**，只改投资信息段、`(3)经营情况`、`(4)退出计划及退出收益`。
- 只有上一期报告中不存在的新投项目，才四节全部新写。
- 用户要求“每个项目一个 Word”时，即对每个项目重复本模式；但静态段落仍取自上一期报告，不得重写。

### B1. 底稿与素材

- 主报告 DOCX（通常为用户工作目录中的基金运营/投后报告）仅作**格式模板**，不修改、不更新其内容。
- 项目数据源：项目 Word、项目表 XLSX 对应 sheet、立项/投决材料、访谈纪要。数据不足时按 xiangmu-biao 项目表口径补齐（投资时间、估值、注册资本、持股比例、协议条款），缺项如实标注。
- 若用户未指定主报告，在当前工作目录及用户提到的文件夹中查找基金运营/投后报告 DOCX；仍找不到时询问用户。

### B2. 输出文件

- 新生成一个独立的 DOCX（不要改动主报告文件），文件名如 `<公司简称>投后报告.docx` 或 `<公司简称>-投后报告_YYYYMMDD.docx`。
- 该 Word 只含该项目的完整内容，结构即基金报告中单个项目块的展开：
  1. 文档标题：`XX项目投后报告`（可含公司全称；若用户希望沿用基金报告风格可加 `4.2.n、公司全称` 作小标题）
  2. 基金投资信息段（投资主体、投资时间、投资金额、投前/投后估值、注册资本、持股比例、交易结构）
  3. `(1)主营业务`：主营业务正文 + 股权结构表
  4. `(2)投资时投资亮点`：带三角符号的亮点子标题与正文
  5. `(3)经营情况`：财务表（历史期间）与经营说明；无实际财报时写文字说明并注明预测数
  6. `(4)退出计划及退出收益`：退出安排、回购条款、预计退出路径

### B3. 格式

- 独立 Word 的字体、字号、表格底纹/边框/列宽、三角编号定义全部沿用主报告项目块的既有格式（深拷贝对应段落与表格 XML），不要自创样式。
- 小标题四号 14 磅、普通正文和表格小四 12 磅（沿用主报告口径）。
- 亮点子标题用主报告的三角编号定义（`w:numPr` 的 `numId`/`ilvl`），不手工输入 Unicode 三角，不用“第一条、第二条”等源文件编号。
- 主营业务首段为普通正文、首行缩进与主报告一致（通常 2 个中文字符），不得使用 Heading 样式。
- 独立 Word 可以带页眉页脚（沿用主报告即可）或简化；目录域不需要（单项目无目录）。
- 表格：股权表无空白尾行、合计行加粗；财务表保留历史期间列。

### B4. 校验与交付

- 结构校验：项目块包含 `(1)`—`(4)` 四个小节、亮点三角正确、表格边框底纹未漂移、正文无意外 Heading/outline level。
- 视觉校验：有 Word/WPS/LibreOffice 时渲染逐页检查三角符号、表格分页、缩进与换行；无渲染引擎时仅结构校验并在交付中披露。
- 交付说明：只交付该项目独立 DOCX，简述项目信息、数据来源与缺口（如缺某期财报、待确认条款）；明确说明未改动基金主报告。

## DOCX 编辑约束

- 优先修改现有 `run.text`；不要用 `paragraph.text=` 覆盖复杂段落。
- 插入完整项目时深拷贝正文 XML 节点，排除源文档 `sectPr` 和尾部空段落。
- 合并前确认源项目没有图片、对象或独立关系；若存在，必须同步复制关系和媒体部件。
- 克隆表格行、列和项目块后，再局部替换文字。
- 用克隆段落/表格重建正文时，必须**清空 body 的全部原有子节点（含末尾 `sectPr`）后只追加一个 `sectPr`**；追加两个会导致分节异常、页眉失效。
- 主报告末节的 `sectPr` 常常不含 `headerReference`（靠前节继承）。生成独立文档时必须补上 `w:headerReference`（默认页眉）与 `w:footerReference`（页码页脚），否则页眉会整体丢失。
- 克隆段落时要剥掉 `bookmarkStart`/`bookmarkEnd`、`w:lastRenderedPageBreak` 和段落级 `w:sectPr`，避免重复书签与多余分节。
- 不修改源文件；最终文件只保存到用户指定输出目录。
- 本技能 `scripts/clone_project_block.py` 是已验证的参考实现：`probe` 打印上一期报告的 body 下标（含三角子标题的 numId），`locate/clone_para/clone_table/set_text/build` 负责克隆模板元素并生成独立文档，`verify` 做结构校验（sectPr 数量、`(1)`—`(4)`、三角条数、字号、意外 outlineLvl）。季度更新时先 `build` 出骨架，再把静态段落按上一期原文填回。

## 校验清单

### 内容

- 模式 A：项目数量正确；投资概况、正文和目录的顺序完全一致；每个项目编号连续且唯一；投资金额合计、项目数和投资比例正确；第五部分数值与基金财务 XLSX 一致，元/万元换算正确。
- 模式 B：仅输出目标项目的独立 Word；项目信息（投资时间、金额、估值、持股比例、条款）与项目表/立项材料一致；未改动基金主报告。
- 季度更新：`(1)主营业务`、`(2)投资时投资亮点` 与上一期报告**逐字一致**（除经用户确认的最小必要增补）；本期新增内容仅限投资信息段、`(3)经营情况`、`(4)退出计划及退出收益`。
- 季度更新：投资信息段已反映本期新一轮融资与持股比例稀释；财务表期间列符合“前两个完整年度＋当年各期累计”的滚动窗口，缺期不编造。

### 项目结构

- 每个项目具有 `(1)`—`(4)` 四个小节。
- 主营业务首段为普通正文、首行缩进与其他正文一致、不会进入目录。
- 每个投资亮点子标题使用参考项目的三角编号定义。
- 不存在“第一条、第二条”等错误自动编号。
- 项目之间恰好空一行。

### 格式

- 小标题 14 磅，普通正文和表格 12 磅；用户另有指定时以最新指令为准。
- 表格列宽、边框、填充颜色和对齐未漂移。
- 新增底纹颜色不得超出模板及源项目已有颜色集合。
- 正文没有意外 Heading 样式或 outline level。

### 文件与视觉

- DOCX ZIP 完整性检查通过。
- 模式 A：重新导出段落和表格结构，确认项目块顺序；设置目录域更新标志并检查 TOC 域存在。
- 使用 Documents 技能的 `render_docx.py` 渲染全部页面并逐页检查：
  - 三角符号、缩进和换行；
  - 表格分页、边框和底纹；
  - 项目间空行（模式 A）；
  - 目录条目和页码（模式 A）；
  - 无裁切、重叠或字体替换。
- 若缺少 LibreOffice/Word/WPS，只能做结构校验，并在交付中披露未完成视觉渲染。
- macOS 下用 AppleScript 驱动 Word/Excel 导出 PDF 常被系统 TCC 拦截（报错 -10004 权限违例），`qlmanage` 也可能报 sandbox 初始化失败；此时不要反复重试，直接改为结构校验并在交付中说明未渲染。

## 交付

- 只交付最终 DOCX，不交付内部 dump、PDF 或页面 PNG，除非用户要求。
- 模式 A：简述新增/重排项目、投资概况、基金财务指标和目录更新情况。
- 模式 B：交付该项目的独立投后报告 DOCX，简述项目信息、数据来源、数据缺口；说明未改动基金主报告。
- 季度更新：明确列出本期相对上一期报告的**变化点**（新融资、新财报期间、持股比例稀释、退出进展），并声明 `(1)主营业务`、`(2)投资时投资亮点` 未作改动。
- 说明任何无法渲染、无法静态更新目录页码或缺少目标季度数据的限制。
