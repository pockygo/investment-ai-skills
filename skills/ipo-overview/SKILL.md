# IPO 项目总览收录流水线

配合 ipo-research skill 使用：ipo-research 产出单个项目的研究报告，本 skill 负责把各项目核心信息摘录进一张横向对比总览表。

## 输入与产物

- **输入**：项目目录（内含 `projects/<公司名>/report/<公司简称>.md` 研究报告，及 `extracts/`、`md/` 辅助判断）
- **总览表**：`~/Desktop/ipo-overview/项目总览.md`（固定位置，桌面 ipo-overview 文件夹专放项目总览）
- **渲染**：`cd ~/Desktop/ipo-overview && python3 render_overview.py`（脚本与总览同目录，skill 内 `pipeline/render_overview.py` 为主副本；冻结表头+首列、三年一期分行显示，适配 1920×1080）

## 收录流程（每个项目一行）

1. **读研究报告**：重点看标题/开头的板块与报告期说明、公司速览章（含关键财务速览表）、现金流章、风险清单章（疑点清单按严重度排序处）、募投章、综合评价。报告里缺的合计数（如拟募资总额）回 `extracts/` 对应模块补。
2. **判断研究档位**：`ls extracts/`——Q1-Q5 文件为 quick 档，01-12 模块为 deep 档。
3. **判断问询轮次**：`ls md/` 看 inquiry1/2/3.md 数量，结合报告正文审核状态表述。
4. **分析日期**：`stat -f "%Sm" report/<公司简称>.md`（macOS），转 YYYY-MM-DD。
5. **追加表格行**（列序固定，见下），然后运行渲染脚本重新生成 HTML 并 `open` 打开。

## 列定义（16 列，顺序不可变）

| # | 列名 | 填写规则 |
|---|---|---|
| 1 | 公司名称 | 全称（含"股份有限公司"） |
| 2 | 所处行业 | 15 字内，核心产品形态 |
| 3 | 公司简介 | 50 字内一句话：核心产品 + 市占率/地位 + 客户或绑定特征；第三方数据注明机构 |
| 4 | 近三年一期营收 | `2023 / 2024 / 2025 / 一期`，万元，" / " 分隔；无则"未披露"；一期非 2026H1 时写 `2026Q1：数值` 前缀（渲染脚本识别） |
| 5 | 近三年一期净利润 | 同格式，注明归母/扣非口径 |
| 6 | 近三年一期毛利率 | 同格式，注明主营/综合口径；无意义时写"不适用" |
| 7 | 拟上市板块 | 创业板/科创板（注明第几套标准）/北交所 |
| 8 | 审核状态 | 申报稿 / 已问询（N 轮已回复）/ 注册稿 / 注册生效 / 终止 |
| 9 | 问询轮次 | 数字 |
| 10 | 拟募资额 | 万元（原文为亿元的换算） |
| 11 | 第一大客户及占比 | 如"中际旭创 53.42%"；匿名客户注明"匿名/豁免披露" |
| 12 | 净现比(最新年度) | 经营现金流净额÷净利润，保留两位，附一句注解（如"2026H1 转负"） |
| 13 | 最严重红旗 | 取疑点清单/风险清单中严重度最高的 1 条，40 字内一句话；这是编辑判断，不是机械摘取 |
| 14 | 研究档位 | quick / deep |
| 15 | 报告 | `[研究报告](../<项目文件夹>/projects/<公司名>/report/<公司简称>.md)`，相对路径从 `~/Desktop/ipo-overview/` 算起；写完后用 `[ -f <路径> ]` 逐条验证 |
| 16 | 分析日期 | YYYY-MM-DD |

## 规则

- 数据全部来自该项目研究报告与 extracts，**禁止编造**，找不到写"未披露"。
- 总览表是初筛工具：简介≤50 字、红旗只放最严重 1 条，细节一律留在各项目报告里。
- 渲染脚本：`python3 <skill目录>/pipeline/render_overview.py <总览.md> <总览.html>`，纯标准库，无依赖。
- 表头注释行（金额单位、期间口径说明）与末尾"列名说明"节保持不动，只追加数据行。
