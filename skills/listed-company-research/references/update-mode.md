# update 档位：已研究项目的增量财报更新

## 定位

`update` 不是重新研究，而是**在既有研究结论上打补丁**：项目已有完整的报告 Markdown、HTML、档案卡、财务时间序列和季度面板；用户新给一期财报（Q1、半年报、Q3 或年报），只更新这一期带来的变化。

核心交付只有两个：

1. `report/<公司简称>_档案卡.md`
2. `report/<公司简称>.md` 及其重新生成的 `report/<公司简称>.html`

季度面板、季度图和财务时间序列属于“报告 HTML 的底层数据”，该补则补；**Excel 台账不在本档位范围内**，不要读写、不要新增 sheet、不要更新列。

## 适用与不适用

适用：

- 项目已完成过一次 `quick` 或 `deep`，`report/`、`timeseries/`、`extracts/` 已存在；
- 新增材料是同一公司的后续定期报告，报告期晚于项目已有最后一期；
- 用户明确说“更新”“补 Q3”“新财报到手”“只更新档案卡和 HTML”。

不适用：

- 从零研究、换公司、换上市主体；
- 只有招股书的拟上市项目（用 `ipo-research`）；
- 用户要求重做估值、重写全篇、补充外部行业研究；
- 用户要求维护 Excel 项目表或财务汇总表（这是独立工作，不进入本 skill）。

## 输入

- 新增定期报告 PDF（必需）；
- 已有项目的 `report/<公司简称>.md`、`report/<公司简称>.html`、`report/<公司简称>_档案卡.md`；
- 已有 `timeseries/财务时间序列.md`、`timeseries/季度财务面板.md`、`extracts/quarter_coverage.csv`；
- 已有 `md/manifest.json` 与历史 `md/*.md`（只用于定位口径，不重读历史 PDF 正文）。

不要求用户提供历史 PDF；也不要求重新下载历史报告。

## 更新流程

### 0. 前置检查与备份

1. 确认新报告期、报告类型、审计状态（季报/半年报通常未经审计）。
2. 确认项目已有档案卡、报告 md、HTML；缺任何一个，先说明缺口，不要假装是 update。
3. 备份将被修改的文件：
   - `report/<公司简称>.md`
   - `report/<公司简称>.html`
   - `report/<公司简称>_档案卡.md`
   - `timeseries/季度财务面板.md`（若会改）
   - `report/charts/quarterly_panel.*`（若会改）
4. 备份命名统一加 `_backup_before_<期间>_<YYYYMMDD_HHMM>`，例如 `博迁新材_backup_before_q3_20261102.md`。

### 1. 只转换新增报告

用 `scripts/ingest_reports.py` 只转换新 PDF，输出到 `md/<期间>.md`，保留 `<!-- pN -->` 页码锚点：

```bash
python3 scripts/ingest_reports.py md <新报告.pdf> --names q3_2026
```

**重要：该脚本会重写 `md/manifest.json`，只保留本次输入。** 必须手动把新条目合并进旧 manifest，不能让它把 20 多期历史记录覆盖成 1 期。合并后核对：

- 条目数 = 历史期数 + 1；
- 每条的 `output` 指向存在的 `md/*.md`；
- `source` 指向 `source/` 或项目约定的原始 PDF 路径；
- `pages` 与新转换文本的页码锚点数量一致。

新 PDF 同时复制到 `source/`，保持项目目录约定。

### 2. 只抽取新增期，不重跑全量

优先只解析新增期：

```bash
python3 scripts/parse_tables.py --md md --index index --out extracts --periods q3_2026
```

注意：

- 该命令可能仍重写 `extracts/fin_all.csv`；若会破坏历史合并结果，先备份，再只把新增期行合并进去。
- PDF 表格常把指标名折行截断（如“归属于上市公司股东的净利润”只剩“利润”）。合并前把新增期的关键行名补全，至少保证：营业收入、归母净利、扣非归母、经营现金流、营业成本、研发费用、应收账款、存货、合同负债、短期借款、长期借款、一年内到期非流动负债、租赁负债。
- 不为了跑通脚本用邻近指标填缺失项。

### 3. 计算单季并核对

季报有两列：`本报告期`（单季）与`年初至报告期末`（累计）。

- **先取“年初至报告期末”累计列**，用“本期累计 − 上期累计”得到单季；
- 若季报另列“本报告期”，用它交叉核对，两者应一致；
- 半年报没有单季列时，用 H1 累计 − Q1 累计；
- 年报的 Q4 用 FY − 9M。

必须逐项核对：收入、归母、扣非、经营现金流。差异要查明是四舍五入、重述还是口径问题，不能带差异往下写。

### 4. 更新季度面板与图（仅在季度覆盖变化时）

如果新增期是 Q1/H1/Q3/FY 中尚未覆盖的季度：

1. 在 `extracts/quarter_coverage.csv` 增加一行：
   `2026Q3,available,q3_2026.md,1-13,`
2. 更新 `timeseries/季度财务面板.md`：
   - 表 A 单季规模与盈利
   - 表 B 单季盈利质量
   - 表 C TTM
   - 表 D 累计口径
   - 表 E 季度营运资金
3. 更新 `report/charts/quarterly_panel_data.csv`，补新季度一行；TTM 不足四季时留空并写原因，不得用零补。
4. 重新生成 2×2 图 `report/charts/quarterly_panel.png` / `.svg`，确保：
   - 所有已有季度都在图上，不抽样、不截断；
   - 低基数异常同比保留；
   - 缺值保留位置并写原因。

若新增期是年报，另需更新 `timeseries/财务时间序列.md` 表 A 的年度行；若是中期/季度，更新表 A2，不混入年度列。

### 5. 更新报告 Markdown

只改与新期有关的部分，不重写全文。按以下顺序检查：

1. **页眉研究区间**：把“2026 年半年报 / 2021Q1–2026Q2”改成含新期的表述。
2. **首页结论**：
   - 先判断新数据是否改变原有判断，再决定是否改“一句话定性”和“三个核心变化”；
   - 不能只在末尾贴一句“Q3 收入 +xx%”，要写清“哪条旧结论被确认、哪条被削弱、哪条仍待验证”。
3. **数据面板**：新增 `2.2b <期间> 单季/累计` 小表，列：本期、上年同期、同比、上季、环比。
4. **利润桥**：新增 `<上年同期>→<本期> 归母利润桥`，至少拆到：收入、成本、毛利、税金及期间费用、其他损益、利润总额、所得税、归母；桥必须闭合。
5. **盈利能力/费用率表**：加一列新期；比率按单季或累计口径标注清楚，不与全年混比。
6. **现金流/应收存货/债务表**：加一列新期；期末值用期末，流量用期间；周转天数注明“期末占用天数”及年化口径。
7. **周期复盘**：若新期改变“上行/下行/复苏”的阶段判断，更新周期段落表与 alpha/beta 归因；不改变则只补一句数据。
8. **风险表**：逐条检查“现象”是否过期；把已缓解的风险降级、把新出现的风险补上，不能只改数字不改判断。
9. **财务速查表**：新增一行新期；明确是单季、半年累计还是 9M 累计。
10. **附录 A 季度表**：补新期行，更新标题区间与图注。
11. **附录 B 抽查表**：至少补收入、归母、扣非、经营现金流、应收、存货 6 项，附原文页。
12. **附录 C 数据来源**：报告份数 +1，注明新期未审计、未重读历史 PDF、哪些分项未披露。

### 6. 更新档案卡

档案卡 schema 冻结，只改内容，不加新章节。至少检查：

- 页眉“数据区间”“研究日期”；
- 第 2 节长期序列：新增一期行；中期/季度行必须标“9M/ H1/ Q3 单季”，并注明未年化；
- 第 3 节周期复盘：只在新期改变阶段判断时改；
- 第 4 节管理层评估：资本配置、FCF 累计、ROE 等只在有新数据时更新；
- 第 5 节竞争地位：新报告未披露客户/份额时，明确写“本期未披露”，不得沿用旧数当新数；
- 第 6 节核心看点：把新期最有信息量的 1–2 个变化写进去；
- 第 7 节核心风险：区分“已缓解”“仍存在”“新出现”；
- 第 8 节当前周期位置：用一句话回答“现在处于什么位置、下一期验证什么”。

### 7. 重新生成 HTML

以更新后的 Markdown 为唯一源：

```bash
python3 scripts/md2html.py report/<公司简称>.md report/<公司简称>.html --title "<公司简称>（<代码>）研究报告"
```

检查：

- 新章节进入目录；
- 表格数量与 Markdown 一致；
- 图表路径存在；
- 旧期间标题（如“2021Q1–2026Q2”）没有残留；
- HTML 中的关键数字与 Markdown、档案卡、季度面板一致。

### 8. 验收

至少完成：

1. **算术**：单季 = 累计差额；同比/环比；毛利率 = 1 − 成本/收入；净利率 = 归母/收入；有息负债 = 短借 + 一年内到期 + 长借 + 租赁负债；FCF = OCF − CAPEX。
2. **跨产物一致**：报告 md、档案卡、季度面板、图表 CSV、HTML 五处的同一指标一致。
3. **原文抽查**：新期至少 6 个关键数字回原文页码。
4. **结论检查**：每条被修改的结论，都能指出“新数据哪一项支持/削弱它”。
5. **缺口列示**：新报告未披露的分产品、客户、产能、汇兑拆分等，明确写“未披露/待核验”，不外推。

## 结论变化判定

| 观察项 | 要回答的问题 | 写法要求 |
|---|---|---|
| 收入 vs 利润 | 利润增速是否追上收入？ | 单季与累计分开说；不能用单季修复掩盖累计仍弱 |
| 毛利率 | 是环比回升、同比回升，还是两者都不是？ | 注明单季/累计；未披露分产品时，不把回升归因于某一产品 |
| 现金流 | OCF 转正来自利润、回款还是应付？ | 同时看应收、存货、应付与有息负债；不能只写“现金流转正” |
| 杠杆 | 有息负债、资产负债率是否继续上升？ | 期末值；与上年末、上季末都比 |
| 营运资金 | 存货去化、应收扩张还是两者同时？ | 用期末占用天数，注明年化口径 |
| 费用 | 研发/财务费用是否有一次性或季节性？ | 季报无法判断时写“待核验”，不编原因 |
| 风险 | 旧风险是缓解、恶化还是没变？ | 逐条改“现象”，不要只改数字 |

## 禁止事项

- 不重读、不重新解析全部历史 PDF；需要历史口径时查已有 md/CSV/档案卡。
- 不重跑完整 `deep` 流程，不重写报告全文。
- 不删除既有章节、表格、图或历史数据点。
- 不把季度数直接和全年数比较，不把 9M 数年化后当全年。
- 不在新报告未披露分产品时，推断“镍基/铜基”“高端/通用”的结构变化。
- 不更新 Excel、项目表、财务汇总表；用户明确要求时，作为独立任务处理。
- 不在 HTML 里手工改数；HTML 必须由 Markdown 重新生成。

## 示例：博迁新材 2026Q3（抽象版）

- 新报告：`2026Q3`，未经审计，13 页。
- 单季：收入 558.5（+94.7%）、归母 91.6（+98.8%）、毛利率 30.8%（环比 +3.4pp）、OCF 258.1。
- 9M：收入 1,448.3（+79.8%）、归母 227.2（+49.9%），利润仍慢于收入。
- 结论变化：
  - 旧结论“2026H1 增收不增利”被限定为“H1 现象”，Q3 单季利润增速已追平收入；
  - 旧结论“现金流失血”改为“Q3 转正、9M 累计转正，但杠杆未降”；
  - 因季报未披露分产品量价，毛利率回升的原因列为待验证，不归因于镍基或铜基。
- 档案卡：新增 `2026Q3（9M）` 行；第 8 节改为“上行中后段、二次加速”，并写明“需连续两个季度守住 30% 毛利率”。
- 不更新 Excel。
